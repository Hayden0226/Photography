# GitHub Action Deployment

This repository includes a deployment and validation workflow at `.github/workflows/deploy.yml`. It is designed for a static SPA deployment, validates pull requests, checks out the private photo source repository during builds, syncs published photos to Cloudflare R2, and publishes `apps/web/dist/` to GitHub Pages on non-PR events.

The workflow runs on pushes and pull requests targeting `main` when these paths change:

- `.github/workflows/deploy.yml`
- `photo-descriptions.json`
- `apps/web/**`
- `packages/builder/**`
- `packages/data/**`
- `packages/hooks/**`
- `packages/sdk/**`
- `packages/ui/**`
- `packages/utils/**`
- `packages/webgl-viewer/**`
- `plugins/builder/**`
- `scripts/**`
- project config files such as `package.json`, `pnpm-lock.yaml`, `config.json`, `builder.config.ts`, and `site.config.ts`

It can also be started manually through `workflow_dispatch` or by the private photo repository through the `repository_dispatch` event type `photos-updated`.

## Jobs

Pull requests run the `validate` job only. It checks out `Jackyhq/Photography-Photos` into `./photos`, standardizes photos locally, builds the manifest, builds the web app, and checks that `apps/web/dist/` exists. It does not push photo changes, sync Cloudflare R2, copy output into the deployment repository, upload a Pages artifact, or deploy.

Pushes to `main`, manual runs, and photo-repository dispatches use the `build-and-deploy` job. This job performs the same build validation, commits standardized photo changes back to `Jackyhq/Photography-Photos`, syncs the published photo tree to Cloudflare R2 under the `photos/` prefix, mirrors the web output into `Jackyhq/Photography-Web`, uploads the Pages artifact, and deploys it.

The workflow uses separate concurrency groups:

- Pull requests use `pr-<number>` and cancel stale runs for that PR.
- Non-PR deployment events use the `pages` group.

## Build Steps

Both jobs perform the shared build steps:

1. Check out the source repository.
2. Check out `Jackyhq/Photography-Photos` into `./photos` with `PHOTO_REPO_TOKEN`.
3. Install pnpm `10.19.0`.
4. Set up Node.js `24` with pnpm cache.
5. Install dependencies with `pnpm install`.
6. Run `pnpm run photos:standardize`.
7. Run `pnpm run build:manifest`.
8. Run `pnpm run build`.
9. Verify that `apps/web/dist/` exists.

The deploy job then performs these additional steps:

1. Commit standardized photo changes back to `Jackyhq/Photography-Photos` with `[skip dispatch]`.
2. Sync `./photos` to Cloudflare R2, excluding `.git/`, `.github/`, `incoming/`, `README.md`, and `.gitignore`.
3. Copy `sitemap.xml` to `googlesitemap.xml` when it exists.
4. Publish the optional IndexNow verification key file.
5. Sync `apps/web/dist/` into `Jackyhq/Photography-Web`.
6. Upload `apps/web/dist/` as a GitHub Pages artifact.
7. Deploy the artifact to GitHub Pages.

## Secrets

The source repository requires these secrets:

- `PHOTO_REPO_TOKEN`: fine-grained PAT with read/write Contents access to `Jackyhq/Photography-Photos`.
- `DEPLOY_REPO_TOKEN`: token used to push static output to `Jackyhq/Photography-Web`.
- `CLOUDFLARE_R2_ACCESS_KEY_ID`
- `CLOUDFLARE_R2_SECRET_ACCESS_KEY`
- `CLOUDFLARE_R2_ENDPOINT`
- `CLOUDFLARE_R2_BUCKET`
- `INDEXNOW_KEY` when IndexNow verification output is needed.

The private photo repository requires `MAIN_REPO_DISPATCH_TOKEN`, a token that can send `repository_dispatch` events to `Jackyhq/Photography`.

## Permissions

The workflow defaults to `contents: read`. The deploy job expands permissions only when it needs to publish:

- `contents: write` to support repository checkout and deploy-side Git operations.
- `pages: write` to publish GitHub Pages.
- `id-token: write` for GitHub Pages deployment authentication.

## Output Targets

The primary deployment artifact is:

```plain
apps/web/dist/
```

The workflow also mirrors that static output to:

```plain
Jackyhq/Photography-Web
```

Photo source files are not tracked in this public source repository. The public site loads photos from `https://photos3.jackyw.cn/photos/`, backed by Cloudflare R2.

## Notes

- `photos/incoming/` is excluded from the manifest and from R2 sync; run `pnpm run photos:standardize` or move files into a real category before publishing.
- Photo-repository commits made by the deploy workflow use `[skip dispatch]` so they do not trigger a deployment loop.
- `pnpm run build` runs the web precheck, which calls the builder CLI before Vite builds.
