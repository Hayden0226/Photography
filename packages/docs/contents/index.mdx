# Jacky's Photography

Jacky's Photography is a customized personal photo gallery based on [Afilmory](https://github.com/Afilmory/afilmory). It keeps the core static-gallery workflow from Afilmory while adding project-specific automation, deployment, photo standardization, bilingual photo metadata, map exploration, and presentation refinements for [photo.jackyw.cn](https://photo.jackyw.cn).

> Source photos live in the private `Jackyhq/Photography-Photos` repository. The local `photos/` directory is only a build-time checkout and is ignored by this public source repository. Do not reuse, redistribute, or publish Jackyhq's photos without explicit written permission.

## What It Builds

The project builds a pure client-side React SPA. Photo metadata is generated before the frontend build and embedded as `photos-manifest.json`, so the deployed gallery can run on static hosting without an application server.

Core user-facing features:

- Responsive masonry photo gallery.
- Responsive WebP thumbnails with JPEG fallback and first-screen image preloads.
- Fullscreen photo viewer with WebGL zoom and pan.
- EXIF, histogram, camera, lens, tag, Live Photo, HDR, and Fujifilm recipe display.
- Command palette and gallery controls for searching by title, localized description, tag, camera, and lens.
- MapLibre-based location explorer for photos with GPS metadata.
- Localized photo alt text, description fallback, and photo detail page metadata.
- Static per-photo HTML pages for `/photos/:id` with canonical, OpenGraph, and Twitter Card metadata.
- Profile links for GitHub, Instagram, Twitter, RSS, and the author homepage.
- RSS, sitemap, PWA assets, and static deployment output.

## Storage Providers

`@afilmory/builder` reads photos through a storage-provider abstraction. The current project uses the local provider against a private photo-repository checkout:

```ts
import { defineBuilderConfig } from '@afilmory/builder'

export default defineBuilderConfig(() => ({
  storage: {
    provider: 'local',
    basePath: './photos',
    baseUrl: 'https://photos3.jackyw.cn/photos/',
    excludeRegex: '^incoming($|/.*)',
  },
}))
```

Supported providers:

- `local`: reads local photo directories; useful for the private photo checkout, development, and self-hosted deployments.
- `s3`: reads S3-compatible object storage with optional custom domains and network tuning.
- `github`: reads photos from a GitHub repository or subdirectory.
- `eagle`: reads an Eagle 4 library and can filter by tags or folders.

## Development

```bash
pnpm install
git clone git@github.com:Jackyhq/Photography-Photos.git photos
pnpm run build:manifest
pnpm dev
```

Useful commands:

```bash
pnpm run photos:standardize
pnpm run photos:descriptions:sync
pnpm run build:manifest -- --force
pnpm run build:manifest -- --force-thumbnails
pnpm run build:manifest -- --force-manifest
pnpm run build:manifest -- --config
pnpm build
pnpm docs:dev
pnpm docs:build
pnpm --filter web type-check
```

`pnpm dev` and `pnpm build` run the web precheck, which calls the builder CLI before Vite starts or builds.

For manual photo descriptions, tag curation, and SEO metadata, see [Photo Metadata](/photo-metadata). For mobile loading details, responsive thumbnails, and chunk-splitting expectations, see [Performance](/performance).

## Photo Workflow

1. Put new photos in `incoming/` or directly in a category folder inside `Jackyhq/Photography-Photos`.
2. Run `pnpm run photos:standardize` to rename incoming files from EXIF timestamps and move them into category folders.
3. Run `pnpm run build:manifest` to scan photos, extract metadata, generate thumbnails, and merge any existing manual metadata from `photo-descriptions.json`.
4. Run `pnpm run photos:descriptions:sync` when new manifest photos need sidecar entries, then fill in titles, `zh-CN`/`en` descriptions, and short editorial tags.
5. Run `pnpm run build:manifest` again after editing `photo-descriptions.json` so the builder plugin can merge those values into the manifest.
6. Run `pnpm dev` for local preview or `pnpm build` for static production output.

## Deployment

The repository includes `.github/workflows/deploy.yml`. Pull requests run the same standardization, manifest, and web build validation without deploying. Pushes to `main` that touch app code, packages, `config.json`, or project configuration run the deployment job. Pushes to `Jackyhq/Photography-Photos` dispatch the same deployment workflow through the `photos-updated` event:

1. Installs pnpm and Node.js 24.
2. Checks out `Jackyhq/Photography-Photos` into `./photos`.
3. Installs dependencies.
4. Runs photo standardization.
5. Commits standardized photo changes back to the private photo repository on deploy events.
6. Syncs published photos to Cloudflare R2 under the `photos/` prefix.
7. Builds the photo manifest and web app.
8. Syncs `apps/web/dist/` into `Jackyhq/Photography-Web`.
9. Deploys `apps/web/dist/` to GitHub Pages.
